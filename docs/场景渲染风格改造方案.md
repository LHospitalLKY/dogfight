# 场景渲染风格改造方案（暗场 · 白模 · 单一红色强调）

目标：把现在的“深蓝冷调 + 队伍色机体 + 城市贴图地面”改成参考图那种 **近黑暗场 + 纯白灰“白模”工业场景 + 浅灰展台 + 只用一种红做强调** 的风格。
约束不变：WSL2 + CPU 软件渲染（`moderngl` 上下文不可用，走 pygame 路径）。机体面数提高后帧预算放宽到**单帧 ≤33 ms（30 fps 帧周期）、HUD ≤11 ms**（实测见 §5）。

---

## 1. 参考图拆解

| 元素 | 参考图做法 | 可提炼的实现参数 |
| --- | --- | --- |
| 场外背景 | 近黑，带 45° 极淡斜纹，四角略压暗 | 底色 `#101114`；斜纹 1 px、每 24 px 一条、白 3% 透明度；暗角径向渐变 8% |
| 场景底板 | 一整块浅灰“展台”，边缘有厚度（能看到侧面），下方柔和投影，与背景脱开 | 顶面 `#D3D6DA`，侧面 `#7A7F87`，厚度按屏幕 ~16–24 px；投影为模糊椭圆、黑 45% |
| 主体模型 | 纯白灰“白模”：无贴图、无高光，只靠环境光遮蔽（AO）与柔和主光读出体积 | 基色 `#E8EAEC`；AO 压到 `#6E7278`；主光 45° 左上、漫反射为主、高光几乎为 0 |
| 边缘 | 轮廓干净，暗背景上靠明度差成形，没有描边线 | 不做外描边；只加“边缘光”提亮掠射面 |
| 地面网格 | 极淡，只作为尺度参照 | 1 px、白 6–8%，间距按取景大小 |
| 强调色 | 全图只有一处红（告警对象 + 标签） | `#FF3B3B`，只用于告警/危险，别的地方一律去饱和 |
| 镜头 | 约 25–35° 俯角的等距（isometric）取景 | 现有 `pitch=26°` 基本吻合，无需改相机 |
| 界面 | 深色胶囊 chip + 白色主按钮 + 细线图标 + 小号大写标签 | 圆角 12 px、底色 `#17181C`、细边 `#2B2D33`、正文白、字距展开 |

一句话：**场景去色（只留白灰 + 一点红），地面由“地图”变“展台”，界面容器向参考图的 chip 靠拢。**

## 4. 实施阶段

### P0 背景层（0.2–0.5 ms）

- 预渲染一张 1600×1000（按窗口尺寸缓存）的背景面：`SCENE_BG` 填充 + 斜纹 tile（`pygame.Surface` 画好 24×24 的一块，平铺 blit）+ 径向暗角（2× 预渲染后 `smoothscale`）。
- 每帧只做 1 次整屏 blit，替换现在的 `screen.fill(BG)`；代价与原来同量级，比“每帧画斜纹”便宜一个数量级。
- 取景变化时不重算，窗口尺寸变化才重建。

**验收**：背景区像素颜色落在 `#101114 ± 3`；帧时间不升（±0.1 ms）。

### P1 地面改“展台”（净省约 3.5 ms，是整套风格的性能来源）

1. 去掉 `city_ortho` 透视贴图路径（`_ground_image` / mip / 雾），地面改成**屏幕空间**的展台：
   - 顶面：把世界地面正方形（`arena` 边界）四角投影成 4 个屏幕点，填 `STAGE_TOP`；再叠 2–3 条预渲染的 1D 竖直渐变条（`smoothscale` 到高度），做出参考图那种上浅下深的柔和过渡；
   - 侧面：把同一四角在屏幕上向下平移 `thickness` 像素（16–24），用 `STAGE_SIDE` 填侧面多边形，形成图纸般的厚度；
   - 投影：预渲染一张 2× 的径向柔化椭圆，按展台宽高 `smoothscale` 后贴在展台下方（`STAGE_SHADOW`）。
2. 网格：`_draw_floor` 保留，但颜色降到白 6–8%、只在展台顶面裁剪范围内画；4 km 格扩大到 8 km（远看更像参考图的细纹）。
3. 地形贴图保留一个开关：`--terrain texture|slab`（默认 `slab`），需要看城市地图时切回去，也作为 P1 的回滚手段。

**代价**：从“每帧透视采样 + 全屏 `smoothscale`”变成“1 次背景 blit + 3 个多边形 + 1 次柔阴影 blit”，预计 ground 5.97 → 1.5 ms 以内；省下的预算够 P2/P3 用。

### P2 白模材质（每帧 0 增量，一次性预烘焙）

1. 模型加载时给每个面算一个 AO 值并存进面数据：
   - 把模型体素化成 0.5 m 格（已有聚类代码可复用），对每个面中心沿半球 8–12 个方向走 3–5 步，命中体素即计遮蔽；`ao = 1 - hits/n`，钳到 `[0.35, 1.0]`。
   - 一次性成本：Su-57 约 500 面 × 12 射线 ≈ 6 千次查询，加载时 <0.2 s；之后每帧不花时间。
2. 每帧着色（沿用现有“相机系一次算完”的矩阵化路径）：

```text
shade = AMB * ao + KEY * max(0, n·l) + RIM * (1 - |n·v|)^2
color = CLAY_BASE * shade        # 按 1/32 分档缓存颜色，键=(ao档, shade档)
```

   `_shaded` / `_shade_base` 的缓存机制保留，只把键从“部件/队伍色”换成 “ao 档 + 明暗档”。
3. 队伍色降级为可选 8% 染色（`--team-tint 0..1`，默认 0）；连队识别改由 HUD 颜色与下方的红/蓝细条承担。

**验收**：同一取景下，机体最亮面 ≈ `#E8EAEC`、最暗面 ≈ `#6E7278`；面片排序/背面剔除逻辑不变（金标场景区允许差异，HUD 区保持 0）。

### P3 语义色与细节

- 唯一饱和色 `ACCENT_RED`：来袭弹、`IN n` 告警、锁定框、RWR 楔形；
- 事件标记：发射点从金色改为米白（`#F3EFE6`），高 G 点改中性灰 `#B9BEC5`；
- 航迹飘带：按机体明暗画灰白（明度 55–75%），不再用队伍色；箭头改白；
- 尾焰：从橙红改为“灰白外焰 + 红芯”，加力才出现红芯；
- 机体加边缘光：`RIM = 0.30`，只在掠射角出现，避免白模在暗背景上糊成一团（这是参考图那种“很干净但不糊”的关键）；
- 若边缘光不够，再加一个兜底：对包围盒轮廓画 1 px 浅灰描边（仅在模型屏幕尺寸 > 120 px 时启用）。

### P4 面板/容器向参考图靠拢（可选，与 HUD 语义共存）

- 圆角 4 → 12 px，底色压到 `#17181C`，细边 `#2B2D33`；
- 标题用小号大写 + 0.6 px 字距（Fira Code 已支持大写，`SIT/TAC/MAN` 那种行保持白/次级灰）；
- 参考图的“仪表条”式读数（`|-|-|-|` + 竖条手柄）可选择性替换现有进度条，但不改 HUD 的绿色刻度语义；
- 告警一律用红色胶囊标签（白字），与场景里的红色对象呼应。

**这一阶段不影响飞行语义，可独立回滚。**

## 5. 性能预算

| 阶段 | 增量 | 预算（p95） |
| --- | --- | --- |
| P0 背景 | +0.1 ms（1 次缓存 blit） | 合计 ≤16.6 |
| P1 展台 | **−3.5 ms**（ground 5.97 → ~1.5） | 合计 ~10 |
| P2 白模 | 0（AO 预烘焙，颜色分档缓存） | 不变 |
| P3 边缘光/飘带 | +0.2 ms（多一次点乘，已在逐面循环内） | 合计 ≤11 |
| 展台柔阴影 | +0.3 ms（1 次缩放 blit） | 合计 ≤11.5 |

结论：这套风格**净省 ~3 ms**，留下的余量用来把机体面数提上去，而不是更慢。

实测（1920×1080、200 帧、seed=3，`scripts/profile_frame.py --strict`）：

| 阶段 | p50 / p95 (ms) | 说明 |
| --- | --- | --- |
| ground | 2.14 / 2.56 | 展台，替代旧贴图地面的 5.97 / 6.00 |
| aircraft | 13.56 / 15.81 | 主模型 SU-57 约 2900 面、F-16 约 3700 面 |
| hud | 8.62 / 10.48 | 姿态框迷你模型约 1100 / 1900 面 |
| **合计** | **25.45 / 29.49** | 约 34 fps（软件渲染） |

预算口径取 30 fps 的帧周期 33.3 ms（向上取 33 ms），给 WSL2 上 ±0.5 ms 的抖动留余量；
多次实测合计 p95 落在 29.5–29.9 ms，折合 33–34 fps。

预算法线优化：模型法线在机体系是常量，逐帧只把光照/视线方向转回机体系后点乘，
省掉每帧逐面叉积与归一化。若需要回到 60 fps，把 `SU57_MODEL`/`F16_MODEL`
的体素（0.03 / 0.28）、`mini_voxel`（0.06 / 0.40）调大一档即可，视觉上仅翼尖略钝。

## 6. 验收与回滚

| 项 | 方法 |
| --- | --- |
| 分区像素对比 | `scripts/visual_golden.py --compare docs/images/golden`：HUD 区必须 `0.000%`，场景区记录差异率 |
| 帧预算 | `scripts/profile_frame.py --frames 200 --strict`（合计 ≤33、HUD ≤11） |
| 三档分辨率 | 1600×1000 / 1920×1080 / 1920×720 截图无溢出、无重叠 |
| 对比度 | 面板正文/次级文字对底 ≥4.5:1（`check_contrast.py`）；红色告警 ≥3:1 |
| 视觉清单 | ① 背景无蓝调 ② 地面无贴图色块 ③ 机体无队伍色 ④ 红色只出现在告警 ⑤ 展台有厚度与投影 ⑥ 缩到 25% 仍能读出机体轮廓 ⑦ 远景不糊成灰块 |
| 回滚 | P1：`--terrain texture`；P2：把 `SU57_MODEL`/`F16_MODEL` 的 voxel（0.03 / 0.28）与 `mini_voxel`（0.06 / 0.40）调大一档即回旧画质；P3：`theme.py` 里 `RIM` 置 0 即去掉边缘光；P4 单独 revert |

金标基线会随风格变化整体重拍一次（和换字体时一样），此后每个阶段只允许场景区变化。

## 7. 风险

- **白模糊在暗背景上**：主要靠边缘光 + AO 对比；必要时开 1 px 轮廓兜底。
- **丢掉城市地图信息**：README/文档里“城市地图地面”的描述要同步改成“展台 + 可选贴图”，默认观感优先。
- **200 km 空域与“小展台”尺度冲突**：展台按相机自适应（只画视野内那段边界，边缘虚化），不做实体 200 km 板。
- **AO 预烘焙改变画面**：与现有金标不可比，需整轮重拍基线（一次）。
- **参考图 UI 与军事 HUD 语义冲突**：HUD 的绿/琥珀刻度保留（可读性优先），只把“容器、字体、告警”向参考图靠。
- **GPU 路径**：WSL2 下不可用，但 `render.py` 仍保留 moderngl 分支；白模着色要在 `LIT_VS` 里同步改（`in_ao` 属性 + 同一套公式），否则切到 GL 会两套观感。

## 8. 已完成的字体、飘带与座舱版面改造

- `theme.py`：`FONT_UI` / `FONT_NUM` 指向 `assets/font/FiraCode-Regular.ttf`（Fira Code），字号 `FS_H1=64 / FS_BODY=22 / FS_SMALL=18 / FS_TINY=14`。
- `render.py` `_CachedFont`：支持传字体文件路径；`tabular=True` 时数字按定宽槽位渲染（18 px 槽宽 11.0 px），其余字符走自然字宽；加单字形栅格缓存，HUD p95 10.05 ms。
- `_value_box` 按实际读数宽度向左扩展，五位高度值不再压框线；`CH/FL` 与 `SIT` 拆到两行，避免 Fira Code 字宽带来的贴字。
- `scripts/check_font_metrics.py`：改按渲染器实际步进校验（步进 11 px、极差 0 px、行高 27 px / 20 px 字形，PASS）；`docs/images/golden/` 已按新字体重拍基线，21 帧 × 三档分辨率分区 diff 全 `0.000%`。
- 航迹飘带横截面由“两块不同亮度”改为 `TRAIL_BANDS=8` 条窄带插值：中心 `1.14` 最亮，向两侧连续降到 `0.98 / 0.82`，高光芯 `1.28×`；展向再按机体滚转做明暗交换，720p–2K 下均无色阶。
- **浅灰展台已删除（本轮）**：§3 的 `STAGE_TOP/STAGE_SIDE/STAGE_SHADOW` 与 §4 P1 的“地面改展台”全部作废，`render.py` 的 `_draw_stage` / `_shadow_surface` / `self._stage_shadow` 已移除。地面只留 8 km 一格的极淡网格（`AIR_GRID`）与空域边界（`AIR_EDGE`）作为高度参照，`--terrain texture` 仍保留城市贴图回滚。分项计时里 ground 从 2.14/2.56 ms 变为 0.00（不再绘展台）。
- **座舱版面改成三块独立面板（本轮）**：红方贴左上、蓝方贴右上，各自是“雷达屏 + 抬头显示仪 + 武器栏”；宽屏并排（雷达 220×272 @1600、280×304 @1920），1280×800 自动改竖排。三块共用 `STATION_FILL=(5,15,11)` / `STATION_ALPHA=214` 深色底衬，只靠队伍色边线区分，比原来的半透明玻璃底衬更容易读数，也更像一套仪表。
