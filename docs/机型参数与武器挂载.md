# 机型参数与武器挂载对照

本文档汇总当前仿真平台已实现与计划新增的机体参数与武器挂载，覆盖 **Su-57、F-16V、J-20 系列（J-20A / J-20S）、J-16、J-15T、F-15 系列（F-15C / F-15E / F-15EX / F-15J）**，并列出实现新机体所需搜寻的三维模型资源。

参数来源以公开资料（珠海航展展板、厂商手册、维基与航空媒体）为主；涉密或未公开数据以工程估计值标注，便于后续校准。所有参数最终落地到 `configs/aircraft/*.yaml` 与 `configs/weapons/*.yaml`。

#### 1.3.1 RCS 标定与单位说明（2026-11 修订）

RCS 的物理量纲是面积（m²），但雷达界常用 **dBsm**（相对 1 m² 的分贝值）：

$$
\mathrm{dBsm} = 10 \cdot \log_{10}\!\left(\frac{\mathrm{RCS}}{\mathrm{m^2}}\right)
$$

即 1 m² = 0 dBsm，0.1 m² = −10 dBsm，0.01 m² = −20 dBsm，0.0001 m² = −40 dBsm。
美国/西方公开资料多以 dBsm 表述（如 F-22 “−40 dBsm”），中国公开资料多直接给平方米，二者换算时极易混淆，本表统一以 m² 为主、dBsm 为辅标注。

**标定基准（同一量级参照）**：

| 机型 | 正面 RCS（本仿真口径） | dBsm | 公开原始值 / 来源口径 |
| --- | --- | --- | --- |
| F-22 | **0.001 m²** | **−30** | 洛马 2009 公开 0.0001 m²（−40 dBsm，“钢弹珠”）；部分中文/分析资料给 0.001 m²。本仿真采用后者作为统一口径 |
| **J-20A** | **0.002 m²** | **−27** | 中国公开资料 0.01 m²（−20 dBsm）；美国官方估计 0.027 m²（−15.7 dBsm）、西方分析 0.027–0.05 m²。本仿真按“与 F-22 同级、J-20 略高 3 dB”归一 |
| **J-20S** | **0.003 m²** | **−25.2** | 双座座舱盖加长，取 J-20A 的 1.5 倍 |
| F-35 | 0.0015 m² | −28.2 | 公开估计值（0.001–0.005 m² 区间） |
| Su-57 | 0.3 m² | −5.2 | 俄方公开估计 0.1–0.5 m² 的中值 |
| F-16V | 1.2 m² | 0.8 | 四代机常规量级（1–3 m²） |
| F-15C/E/EX/J | 5–6 m² | 7.0–7.8 | 公开估计 5–10 m²，部分俄/日资料给到 25 m² |

**结论与取舍**：

- 公开资料对 F-22 与 J-20 的正面 RCS 分歧很大：F-22 有 0.0001 m²（−40 dBsm）与 0.001 m²（−30 dBsm）两种口径，J-20 有 0.01 m²（−20 dBsm）与 0.027–0.05 m²（−15.7 ~ −13 dBsm）两种口径，直接对比会得出相差 1–2 个数量级的结论。
- 按“二者统一数量级、J-20 略高于 F-22”的要求，本仿真把 F-22 取 **0.001 m²（−30 dBsm）**、J-20A 取 **0.002 m²（−27 dBsm）**，只差 3 dB（回波功率约 2 倍）。这是**归一化后的仿真口径**，不是对真实 RCS 的断言；若改用洛马 0.0001 m²，J-20 的相对差距会回到约 13 dB（2 个数量级），探测距离差约 1.9 倍。
- 侧向/后向：J-20 因鸭翼、腹鳍与喷口遮挡，侧后向优于四代机但不如 F-22 的严格修形，故取 0.5 / 1.0 m²；这一比值也用于体现“前向优化、侧后向变差”的隐身特征。

**为什么 F-15 的 RCS 远大于 F-16？**

RCS 不是简单按重量走，而是“特征面积 × 反射率 × 朝向”的综合结果。F-15 相比 F-16 大 4–8 倍，主要来自：

1. **特征尺寸大**：F-15 翼面积 56.5 m²、机长 19.43 m，约为 F-16（27.9 m²、15.06 m）的 2 倍与 1.3 倍；RCS 与投影面积近似成正比。
2. **强反射结构多**：F-15 是双发宽机身，两台发动机短舱、大面积平尾/垂尾、平直翼面与尾喷口形成大量镜面与二面角反射；F-16 为单发细长机身，边条与座舱融合更好，垂尾和尾翼面积更小，缺少大块直角反射面。
3. **外挂与改型**：F-15E/EX 的保形油箱（CFT）是两片大平面，外挂吊舱与挂架进一步形成角反射器，侧向 RCS 因此从 15 升到 18 m²；F-16V 通常按干净构型或少量外挂计算，侧向仅约 3 m²。
4. **数值对照**：公开估计 F-15 为 5–10 m²（部分资料 25 m²），F-16 约 1–3 m²，比值约 4–8 倍，与上述尺寸/结构差异一致。

> 仿真中 `rcs_scale()` 对 RCS 取下限 0.001 m²（F-22 的 0.001 恰好不被截断，洛马 0.0001 会被抬到下限），并把 RCS 按四次方根换算成探测距离比例；因此 J-20A 的 0.002 m² 与 F-15EX 的 5 m² 的探测距离比约为 `(0.002/5)^0.25 ≈ 0.14`，即同一雷达对 J-20 的发现距离约为对 F-15 的 14%。

### 3.2 机炮差异

**固定鸭翼怎么落进仿真**：俯仰分配原本按“有鸭翼就由鸭翼包办”写的——只要 `canard_area > 0` 就进入鸭翼分支，平尾分支不再执行。固定鸭翼如果照原样打开，会得到一个偏度恒为 0、却把平尾旁路掉的飞机。因此 `sim.py` 的判断改为 **`canard_deflect_max > 0` 才走鸭翼俯仰分支**（迎角环增益同理）；固定鸭翼只进入升力、涡增升、下洗三项计算。

按当前参数，固定鸭翼在全机升力上贡献约 **+3% CL**（10° 迎角时 CL 0.681 → 0.709），当地迎角超过 14° 后鸭翼自身先失速、涡增升按 `canard_breakdown` 衰减；`canard_post_stall_alpha_deg: 0` 表示它不提供过失速配平，J-15T 做不出 J-20 那种靠鸭翼维持的大迎角动作。

### 4.4 模型搜寻注意事项

1. **坐标系与轴向**：three.js 导出器按 `converter` 字段换算原始 OBJ 的轴向（`su57` / `f16` / `j20` / `f15` / `j16` / `j15t` 六个换算器，后两者共用侧卫家族的换算逻辑：纵轴 X、机头 +X、+Y 向上），新模型需在 `dogfight/view/__init__.py` 的 `CONVERTERS` 里注册。
2. **材质与抽稀**：`keep_materials` 用于体素抽稀后的俯视轮廓，需在 Blender 中确认材质名。
3. **弹舱与外挂**：J-20 的内置弹舱在 Web 端渲染完整模型时不显示挂载；F-15E 的保形油箱与吊舱需与机体合并或单独建模。
4. **面数控制**：Web 端实时渲染，单机体建议三角面数控制在 20 万以内。高模（百万面级）可在 `web` 下加 `decimate_m: 0.04`，导出时按 4 cm 体素聚类、并用二次误差把聚类代表点放到局部主平面上（平板不会出现体素台阶），只在导出副本上做、原始 OBJ 不变；J-16 由 98.9 万面降到 16.0 万面，J-15T 由 79.2 万面降到 14.1 万面。体素尺度不要大于薄翼面厚度（侧卫垂尾内外蒙皮只隔约 7 cm）。

### 4.5 涂装贴图（DDS → WebP）

原始模型自带的 DDS 涂装不直接进浏览器：这些文件是 4096² 未压缩 BGRA（单张约 67 MB），既没有 GPU 压缩格式也没有 mipmap。导出时按下面的链路处理（`web.textures: true` 开启）：

1. **取图**：读模型同名 `.mtl`，取机体材质（面数最多的那个，如 J-16 的 `j_16_d_a_n_d_l_c_d_m_c_b`）的 `map_Kd`；法线图按 `xxx_c.dds` → `xxx_n.dds` 的命名约定找。
2. **烘焙**：缩到最长边 2048，颜色图 sRGB WebP（q88）、法线图线性 WebP（q92），输出 `static/models/<file>_color.webp` / `_normal.webp`。J-16 为 513 KB + 588 KB。源文件没变时按 mtime 跳过。
3. **UV**：`read_obj(with_uv=True)` 读 `vt` 与角点 UV，聚类抽稀只改顶点位置、逐角保留 UV（不做平均，否则 UV 接缝处会被糊成一片），导出写 `vt` 与 `f v/vt`。机体面 UV 必须落在 [0,1] 内（J-16 / J-15T 均为 100%）；挂载物常是平铺 UV，不参与贴图。
4. **前端**：`meta.json` 的 `aircraft.<name>.textures` 给出两个 URL，`camoMaterial` 挂 `map`（sRGB）与 `normalMap`（`normalScale` 0.65），同时关闭程序化迷彩、机头压深、垂尾军徽与尾喷金属遮罩——这些细节贴图里已经有。贴图未就绪或加载失败时自动退回程序化涂装。
5. **兜底**：原始 DDS 被清掉但已烘焙的 WebP 还在时，导出继续沿用旧 WebP，避免该机型突然丢掉涂装（重新烘焙前需把 DDS 放回 `assets/aircraft/textures/`）。

- **超时局分成两类**：5 局双方满血、按“剩余军推续航”判红胜（F-15EX 内油 + CFT 的军推续航更久）；6 局按血量判定，红蓝各 3 局 —— 红方为 4（44.1 vs 28.3）、12（100 vs 32.9）、15（100 vs 54.8），蓝方为 8（50.8 vs 100）、9（29.3 vs 100）、19（24.7 vs 100）。
- **近距交换不再单向**：F-15EX 用 M61A1 的高射速与 AIM-120C 的近距补射赢下 4 次击落；J-20A 新增的 GSh-30-1 机炮与 PL-10 也在近距局生效。最大过载整体略降（多数 6.8–8.2 g，少数仍到 8.8 g），垂直机动被能量门限拦住后不再靠一次性大过载“撞角度”。
- **雷达静默策略的副作用**：`auto` 策略下双方在远距保持雷达关机，直到进入约 40 km 才开机；若改用 `always` 或开启预警机，J-20A 的隐身先手会更明显（F-15EX 的探测距离仍受 RCS 四次方根限制）。本表按场景默认配置（无预警机）统计。

> 说明：该结果依赖本文 §1.3.1 的 RCS 标定与 `configs/aircraft/*.yaml` 的推重/挂载参数，仅用于比较参数趋势，不代表真实空战结论。此前 J-20A 因“无内置机炮”被 Agent 误判为弹药耗尽而持续脱离，已修正为“机炮与导弹余量同时为空才脱离”；之后又修正了殷麦曼机动“带坡度进入 → 半筋斗退化成盘旋爬升”、低空改出被防御判据抢占，以及“过载/动能不足就起步、改出阈值过晚”导致的失速盘旋滑落（详见《仿真模型与战术设计.md》§4.9.1），5 组抽查中两机的垂直机动最低速度都保持在 1.6 倍失速以上。本轮在 J-20A/S 上补装 GSh-30-1 机炮，并把 PL-15 改为双脉冲推力模型（§3.6），因此上表与上一版（10:10）不可直接对比。

## 7. 新增机体 / 更新模型的操作流程

按顺序做完下面五项；第 4 项可用脚本一键完成（`.trae/skills/add-aircraft/`）。

### 7.1 模型与导出

1. 原始模型放到 `assets/aircraft/<file>.obj`（有 `.mtl` 和贴图目录一并放好）。
2. 在 `configs/assets/models.yaml` 的 `aircraft` 下登记：`length_m`、`voxel_m`（俯视轮廓用）、`web.source / file / converter / decimate_m`；带 DDS 涂装的加 `web.textures: true`（见 §4.5）。
3. `version` 递增（`web-obj-vN`）。这会触发**全部**模型重导，`dogfight/web/static/models/*.obj` 与 `meta.json` 需一并提交。
4. 在 `dogfight/view/__init__.py` 实现 converter 并注册到 `CONVERTERS`，要点：
   - 轴向与机头方向**用座舱座椅/内饰的位置确认**，不要按文件名猜；
   - 机体材质取面数最多的那个，其余归 `stores`（挂架、导弹、副油箱、玻璃）；
   - 座舱盖：材质名含 `glass` + 机头 12%–28% + 高度 ≥ 50% + 中线 ±5%；
   - 喷口：在机尾发动机带内按 0.5 m 窗口密度找喷口环并取质心。**不能**用“机尾最外点 ± 翼展比例”，侧卫的尾梁伸在喷口之后，会把尾焰放到发动机舱外；
   - `decimate_m` 必须小于薄翼面厚度（侧卫内外蒙皮只隔约 7 cm，取 4 cm）；抽稀用 `cluster(..., quadric=True)`。

### 7.2 仿真配置

1. 新建 `configs/aircraft/<id>.yaml`：几何/质量、推力、`cd0`/展弦比/`cl_max`、结构过载、燃油、机炮、操纵面（`elevon` / `all_moving_fin` / `canard`）、RCS 三档、雷达/IRST、agent 参数、挂载。
2. 有特殊气动面要改 `dogfight/core/sim.py` 并用 CL–迎角曲线验证。例如固定鸭翼必须 `canard_deflect_max: 0`，且俯仰环的 `a_can` 分支要加 `canard_deflect_max > 0` 条件，否则平尾会被旁路。
3. 需要新对阵就加 `configs/scenarios/*.yaml`，跑 seeds 1–3 确认能正常结束。

### 7.3 Web 观战端

1. 俯视轮廓：`tools/maintenance/build_silhouettes.py` 的 `builds` 加一条 → 生成 `assets/silhouettes/<id>_top.png` → 在 `app.js` 的 `SIL_IMAGES` 注册。
2. 涂装：`CAMO_SPECS` 必须补条目（渐变/底色、`mark` 军徽、`markCenter / markSize / markLateral`）。缺条目会让前端在 `camoTexture()` 里抛 `Cannot read properties of undefined (reading 'image')`，整个画面黑掉。
3. 尾焰位置来自 `meta.json` 的 `engines`，导出后确认落在喷口中心。
4. 涂装贴图：`web.textures: true`，并在 `CAMO_SPECS` 保留一条兜底涂装（贴图缺失时使用）。烘焙与 UV 细节见 §4.5。
