# 画面精致化方案（第二版 · 软件渲染路径）

本方案针对当前代码的实际瓶颈重新制定，不再沿用第一版中"加面数就能变精致"的假设。
所有数字都来自本机实测：`SDL_VIDEODRIVER=dummy`、1920×1080、seed=3、200 帧、`scripts/profile_frame.py --strict`。

---

## 0. 一句话结论

画面不够精致，**不是模型面数不够，而是三件事**：

1. `pygame` 软件路径没有深度缓冲、没有多重采样、没有逐像素着色——所有面都是平涂，所以放大后一定出现硬边、色阶和穿插；
2. 机体用体素聚类降面，体素化会把翼前缘、进气道唇口切成方块，面片法线也一起被量化，光照读起来像"低模"；
3. 飘带用 8 条平涂窄带拼横截面，颜色是分段常数，8 条带在 10 px 宽度上各占 1.25 px，放大看就是阶梯。

所以顺序必须是：**先腾出预算 → 先解决边缘与色阶（抗锯齿/降采样）→ 再换更好的降面算法 → 最后才是加特效**。
直接加面数会把单帧从 29 ms 推到 60 ms 以上，只会更卡，不会更精致。

## 1. 现状实测与既有约束

| 项 | 现状 | 位置 / 参数 |
| --- | --- | --- |
| 分项帧时间（p50/p95） | ground 2.14/2.56、aircraft 13.56/15.81、trails 0.62/0.91、hud 8.62/10.05、合计 25.45/28.98 ms | `scripts/profile_frame.py` |
| 帧预算 | 单帧 ≤33 ms（30 fps）、HUD ≤11 ms | `--strict` |
| 机体面数 | Su-57 ≈2900、F-16 ≈3700（主视图）；迷你模型 1100 / 1900 | `SU57_MODEL` / `F16_MODEL` 的 voxel |
| 降面算法 | 体素聚类（同格顶点取平均） | `_load_obj_model.cluster()` |
| 着色 | 平涂：`AMB·AO + KEY·|n·l| + RIM·(1-|n·v|)²`，逐面一个颜色 | `_draw_model`、`_draw_attitude_model` |
| 深度 | 画家算法（按面心深度排序），无 z-buffer | 同上 |
| 飘带 | 半宽 5 px、8 条窄带平涂、中心 1.14 → 两侧 0.98/0.82、高光芯 1.28× | `TRAIL_*` |
| 文本 | pygame.freetype + `_CachedFont`（数字定宽 11 px 槽），Fira Code 64/22/18/14 | `theme.py`、`render.py` |
| 颜色分层 | `BG / PANEL / HUD / 告警红` 四层 | `theme.py` |
| GL 路径 | 存在（`_init_gpu` / `LIT_VS` / `_gpu_scene`），本机取不到 GL 上下文，实际走软件路径 | `render.py` |
| 展台 | 已删除：地面只留 8 km 一格的极淡网格与空域边界（`AIR_GRID/AIR_EDGE`） | `_draw_floor` |

**这条约束最关键**：软件路径下"每多一个面"都要走一次 Python 投影 + 排序 + `pygame.draw.polygon`，
实测约 **2.4 µs/面**。也就是说：

- +3000 面 ≈ +7 ms；
- +10000 面 ≈ +24 ms（直接超预算）；
- 想要 4 万面的原始 OBJ（Su-57 原始规模）在软件路径下是 100 ms 量级，不可行。

因此"模型更精细"必须走 **减面但不减形**（保特征简化）+ **视觉抗锯齿**，而不是堆面。

---

## 2. 总原则

1. **分层思维**：3D 场景层、飘带层、仪表层、文本层各自独立优化；能缓存的绝不逐帧重算。
2. **每阶段都要有可回滚开关**（CLI 参数或 `theme.py` 常量置 0）。
3. **每阶段都要能验收**：金标分区 diff、`profile_frame --strict`、三档分辨率截图。
4. **不以"看起来更花"为目标**：目标是轮廓干净、明暗连续、色阶消失、信息层级清楚。

## 3. 阶段方案

### P0 清场与腾预算（必做，收益最大）· 删展台已完成

**删除展台**（用户已明确要求，本轮已落地）。展台原先的价值只有"给出一个地面参照"，但它同时带来：

- 每帧一次投影 + 4 个多边形 + 一次 `smoothscale` 柔阴影（2.1–2.6 ms）；
- 浅灰大色块在暗场里抢视觉重心，机体反而退到次要位置；
- 与"空中狗斗"的题材不匹配。

替代做法（不新增成本）：

- 背景保持 `SCENE_BG` + 45° 斜纹 + 暗角；
- 空域边界改成 **4 条 1 px 虚线**（预渲染 dash tile 平铺）；
- 地面网格保留，但颜色从 `STAGE_GRID` 降到 `(255,255,255,7%)` 的极淡线，只在相机俯角足够时画（俯角 <12° 时整层跳过）；
- 机体投影线（现有的竖直投影）保留——它才是真正有用的高度参照。

**顺带做的三件省预算的事**：

| 改动 | 做法 | 收益 |
| --- | --- | --- |
| 飘带抽稀 | 屏幕长度 < 2 px 的相邻采样段合并成一段（当前 60 m 采样，远景段极多） | trails −0.2 ms，且减少重叠闪边 |
| HUD 底衬合并 | 每个站点的 8 块半透明底衬合成 1 张缓存面，一次 blit | hud −0.4 ms |
| 只画视野内刻度 | 航向带/俯仰梯的循环先在屏幕矩形里做区间判断，跳过不可见项 | hud −0.2 ms |

**验收**：合计 p95 ≤ 26 ms，ground ≤ 0.6 ms，画面里不再出现浅灰大色块。

### P1 抗锯齿：先消灭锯齿与色阶（本期观感提升最大）

软件路径没有 MSAA，但有三条便宜的路：

#### P1.1 3D 场景层超采样（只对需要的地方）

- **不要整屏 2×**（成本 ×4，直接爆）。
- 对**机体包围盒**做 1.6× 超采样：把机体画进 `bbox×1.6` 的离屏面，再 `smoothscale` 回 1× 并 blit。
  机体屏幕尺寸约 400×300，代价 ≈ 渲染面积 ×2.56（aircraft 15.8 → 约 30 ms）——**太贵，否决**。
- 折中：**1.25× 超采样**（面积 ×1.56，aircraft +7 ms），只对"屏幕长度 > 260 px 且离相机最近的一架"启用；
  另一架走 1×。合计约 +4 ms，仍在 P0 腾出的预算内。

#### P1.2 轮廓羽化（成本 ~0.3 ms，性价比最高）

机体画完、画飘带之前，对机体包围盒做一次**边缘羽化**：

1. 取机体 bbox；
2. 用机体最外轮廓（按面法线朝向视线 > 0 的边集）画 1 px 半透明描边，颜色取 `CLAY_BASE` 与背景的混合；
3. 描边 alpha 随"该边两侧明度差"加权，明暗交界处才描，平坦处不描。

这一步能消掉暗背景上最刺眼的"台阶感"，成本只是一次边集遍历（预烘焙在模型里，逐帧只做投影）。

#### P1.3 FXAA-lite（兜底，约 1.2–2 ms）

如果 P1.1/P1.2 仍不够，对**整个 3D 层 bbox**（不含仪表）做一次 numpy 版 FXAA：

- 亮度梯度阈值 0.12，沿梯度方向在 2 邻域内做加权混合；
- 只在机体 + 飘带 + 导弹的联合 bbox 内跑，1920×1080 下约 600×500 = 30 万像素，numpy 一次约 1.5 ms；
- 开关：`--fxaa 0|1`。

#### P1.4 小图元 AA

- 菱形、圆、三角标记改用 `gfxdraw.aapolygon` / `aacircle`（数量少，成本可忽略）；
- 1 px 直线继续用 `pygame.draw.line`（本来就是硬 1 px，反而清楚）；
- **文本不动**：freetype 已带 AA，再处理只会糊。

**验收**：1920×1080 截图放大 200%，机体轮廓无连续台阶；`aircraft` p95 ≤ 19 ms；合计 ≤ 30 ms。

### P2 模型：保形减面 + 平滑法线（画面"精细度"的核心）

#### P2.1 换掉体素聚类

体素聚类的问题：它**按空间格取平均**，翼前缘、进气道唇口这类"薄特征"会被拉成方块，
法线也被量化成少数几个方向，于是光照出现大片同色的三角块。

改用 **QEM 边塌缩（Quadric Error Metric）**：

- 每个顶点累积二次误差矩阵（3×3 对称，10 个系数）；
- 每次塌缩代价最小的边，落到最优位置；
- **特征边保护**：法线夹角 > 55° 的边、边界边、材质交界边不塌缩（翼前缘、唇口、喷口、舱盖框得以保留）；
- 目标面数：Su-57 5500、F-16 6500（比现在多 ~70%，成本 +8 ms，需 P0+P1 让出的预算）。

一次性开销：加载时 <1.5 s（numpy 实现），之后每帧不变，可缓存成 `.npz` 或直接写回缓存文件。

**预期**：面数 +70% 但形状误差 <0.4% 机长，翼前缘从"锯齿块"变成"直线"。

#### P2.2 平滑法线（逐顶点法线）

- 加载时算**顶点法线**（按面法线面积加权平均），与现有面法线一起存；
- 展开以下两个用途：
  1. **边缘光**改用顶点法线（轮廓一圈亮度连续，不再一折一折）；
  2. **面内渐变**：对屏幕面积 > 900 px² 的面，按重心分 3 个子三角形，每个子三角形颜色在三个顶点法线的着色值之间插值（等价于一次三角化 Gouraud）。只对大面做，总数控制在 +800 面以内（约 +2 ms）。

#### P2.3 远景 LOD

- 机体屏幕长度 < 90 px 时，改用**预渲染 16 方向 sprite**（加载时从主模型正交渲染一圈，`.png` 缓存）；
- 远景成本从 ~2 ms 降到 ~0.05 ms；省下的预算给 P1.1 近距离超采样。
- 判据按屏幕长度而不是世界距离，保证缩放/跟随镜头都正确。

#### P2.4 模型细节（可选，按预算排期）

| 细节 | 做法 | 增量 |
| --- | --- | --- |
| 舵面偏转 | 平尾/方向舵按当前指令绕铰链转 ±8°，直接从现有面里拆出对应面组 | +0.3 ms |
| 加力喷口扩张 | 喷口环按 `ab` 在 0–12% 直径间缩放（顶点沿径向偏移） | +0.1 ms |
| 挂架与挂弹 | 机翼下低模挂架 + 弹体（复用导弹低模） | +0.4 ms |
| 起落架收起 | 已切（`GEAR_Y`），无需再处理 | 0 |
| 座舱盖反射 | 舱盖面加一条随视线移动的浅色高光带（预烘焙 mask，逐帧只改 alpha） | +0.2 ms |

#### P2.5 削弱"低模感"的最后一个开关：AO 质量

现有 AO 用"点云半球遮挡"近似，半径固定，导致翼根/进气道口偏灰。
改为**沿法线半空间 24 方向射线**（加载时一次，numpy 向量化），凹处更黑、凸面更亮，
观感上会立刻从"卡通白模"变成"量产的金属壳"。这一项**零帧成本**。

**验收**：机体 p95 ≤ 19 ms；同一取景下翼前缘为直线；金标场景区差异允许，HUD 区必须 `0.000%`。

### P3 光影与空气感

| 项 | 做法 | 增量 |
| --- | --- | --- |
| 双光 | 主光（左上冷白）+ 补光（右下暖灰，强度 0.25）+ 环境项，轮廓不再"半黑半白" | 0（同一次点乘） |
| 大气透视 | 逐面颜色按相机距离混向 `SCENE_BG`（线性 8–40 km），远近层次分开 | 0 |
| 接触阴影 | 机体在 `z_floor` 上的软椭圆（预渲染，按高度/距离缩放 alpha） | +0.2 ms |
| Bloom | 亮度阈值 → 0.25× 降采样 → 两次 box blur → 加色叠加；只对尾焰、发射星标、导弹爆炸 | +1.2 ms（0.25× 面积极小） |
| 尾焰分层 | 外焰（半透明白）+ 内焰（红）+ 激波钻石（加力时 3 个小菱形） | +0.3 ms |
| 导弹尾烟 | 每 3 帧在弹尾插一个衰减粒子（复用 `_draw_counters` 的缓存圆） | +0.3 ms |
| 高 G 翼尖涡 | 拉过载 >5 g 时在翼尖画两条细白弧，随过载加长 | +0.2 ms |

**验收**：暗场下机体与背景的轮廓可辨（缩到 25% 仍能读出机形）；Bloom 不糊住读数。

### P4 航迹飘带：锯齿与渐变不连续

#### 问题定位

- **锯齿**：飘带是四边形，斜向时边是硬像素，长航迹的斜边会出现整条阶梯；
- **渐变不连续**：8 条带各占 1.25 px，颜色是分段常数；加上中心高光芯（1.28×）与两侧 0.98/0.82 之间没有过渡，放大就能数出 8 条色阶。

#### 方案

1. **半分辨率飘带层 + 双线性放大**（同时解决锯齿与色阶）：
   - 新建 0.5× 的 `SRCALPHA` 层，只覆盖飘带联合 bbox；
   - 8 条带在 0.5× 下变成 2.5 px 宽，`smoothscale` 放大回 1× 时自动插值 → 色阶消失、边缘变柔；
   - 代价：bbox 面积 ×0.25 的绘制 + 一次 `smoothscale`（约 +0.6 ms，抵消 P0 抽稀的收益）。
2. **横截面连续化**：把横截面做成 1×N 的渐变条（预渲染 32 级 alpha），按段 `rotozoom` 后拉伸——
   对小段数量多的情况反而更贵，因此只在"段长 > 6 px"时使用，短段继续用插值带。
3. **段间连接**：相邻四边形共享边不再各画一半（避免重叠处的双倍 alpha 闪点），端点加半圆帽（`circle` 两次）。
4. **明暗语义**：亮度不再固定中心最亮，而是 `亮度 = 基础 × (1 + 0.35·gLoad + 0.2·ab)`，
   机动越猛、加力越足，航迹越亮——让飘带本身成为"能量状态"的可视化。
5. **与机体的遮挡**：飘带整体画在机体之前（现状），近距离时按段插入机体前后会有穿插；
   改为按"段心深度 vs 机体 bbox 深度"决定是否把该段延后到机体之后绘制（只对最近 8 段判断，成本可忽略）。

**验收**：飘带放大 300% 无色阶、无阶跃；斜向航迹边缘为柔和过渡；trails p95 ≤ 1.6 ms。

### P5 文本与容器的精致化

#### P5.1 统一 Panel 组件

现在 `_panel_bg` 只有"填充 + 圆角 + 强调条"。升级为四层（全部 2× 预渲染缓存，逐帧零成本）：

1. **外投影**：向下 4 px、模糊半径 6 px、黑 28%；
2. **描边**：1 px `PANEL_EDGE_HI`（上/左）+ `PANEL_EDGE`（下/右），模拟受光边；
3. **内高光**：顶边内侧 1 px 白 6%；
4. **底衬**：`PANEL_FILL` 渐变（顶 96% → 底 88% 亮度），让面板不是一块死色。

圆角从 4 px 提到 **10 px**（2× 画再 `smoothscale` 得到 AA 圆角，避免锯齿角）。

#### P5.2 标题与标签

- 面板标题改 **大写 + 0.6 px 字距**（逐字 advance 累加，`_CachedFont` 已支持）；
- 标题下加 1 px 分隔线（`PANEL_EDGE` 60%）；
- 标签/单位降到 `SUB` 色（对底 ≥4.5:1），主读数用 `TEXT`；
- 一切数值右对齐到 4/8 栅格，`tabular` 定宽槽保证滚动不抖。

#### P5.3 读数框（HUD 滚条）

- 方框改 **1 px 描边 + 内侧 1 px 深影**，四角切 2 px 斜角（比纯矩形更像仪表）；
- 框上下 6 px 各加一条**渐隐遮罩**（预渲染 1×6 alpha 梯度），刻度从框后滚过时不会突兀截断；
- 中央航向框左右各加 1 px 短竖线，强化"锁在中间"的读法。

#### P5.4 语义色与对比度

- 主读数（白）/ 辅助（60% 灰）/ 单位（45% 灰）/ 告警（`ACCENT_RED`）/ 锁定（黄）五级，不再出现第六种颜色；
- 对比度门槛沿用 `scripts/check_contrast.py`：正文 ≥4.5:1、告警 ≥3:1；
- 红色只用于"需要立刻反应"的三类：来袭弹、锁定完成、HP 归零预警。

#### P5.5 字重

`assets/font/` 里已有 `FiraCode-Medium.ttf`（当前未用）。建议：

- 标题/面板名用 **Medium**，正文与数字继续 Regular；
- 这样在 22 px 标题上会明显更"实"，而读数不受影响。

**验收**：三档分辨率下面板圆角无锯齿；任何面板标题与读数间距 ≥4 px；金标 HUD 区重拍后 `0.000%`。

### P6 后处理与色彩

| 项 | 做法 | 增量 |
| --- | --- | --- |
| 色调映射 | 暗部抬 2%、高光在 92% 处软滚降，避免辉光死白 | 0（查表） |
| 色彩分级 | 阴影偏冷（+3 蓝）、高光偏暖（+2 红），与"冷暗场 + 暖告警"一致 | 0（查表） |
| 抖动 | 背景渐变加 ±1 LSB 有序抖动，消除大面渐变的色带 | +0.3 ms（只在背景重建时做一次） |
| 全局暗角 | 已有（P0 背景面） | 0 |

**注意**：色调映射与色彩分级要在**整屏合成后**做一次，用 numpy 查表（1920×1080 ≈ 2M 像素，约 4–6 ms）——**太贵**。
折中：只在 P0 重建背景面时应用，3D 图层保持线性输出；观感差异可接受，成本为 0。

## 4. 与 GPU 路径的关系（重要）

上述 P1、P2.2、P3、P6 里很多"近似"都是软件路径的妥协。一旦能拿到 GL 上下文（`_init_gpu` 成功），
同样效果可以用标准手段做到几乎免费，且质量更高：

| 软件路径妥协 | GL 路径正解 | 备注 |
| --- | --- | --- |
| bbox 1.25× 超采样 | 整屏 MSAA 4×/8× | 只需改 `pygame.display.gl_set_attribute` |
| 顶点法线伪 Gouraud | 片元着色器逐像素法线插值 | `LIT_VS` 增加 `in_nrm` 平滑插值即可 |
| 边缘羽化描边 | MSAA 自动处理 | 可删 |
| Bloom（0.25× 两遍 blur） | 半分辨率高斯 + 双三次升采样 | 质量更高，成本更低 |
| 画家算法穿插 | 深度缓冲 | 彻底解决飘带/机体穿插 |

**结论**：软件路径的精致化上限是"干净"，GL 路径的上限是"通透"。
建议保留 `--no-gpu` 的软件路径作为兜底，同时把 P1/P2/P3 的着色公式同步进 `LIT_VS`，两条路径观感一致。

## 7. 风险

- **QEM 实现比体素聚类复杂**：需要 1.5 s 级加载时间与缓存文件；若出问题，`--mesh voxel` 立即回退到现状。
- **半分辨率飘带层会增加一层离屏面**：窗口尺寸变化时必须重建，否则会拉伸模糊。
- **超采样只对最近一架生效**：两机同框且都很大时（近距格斗），另一架仍有台阶——这是预算换来的，文档里要说明。
- **Bloom 与读数对比度冲突**：必须保证 Bloom 只作用于 3D 层，绝不上仪表层。
- **文本容器改圆角 10 px 会改变所有金标**：一次重拍即可，之后 HUD 区应保持 0.000%。
- **删除展台后"地面参照"消失**：只靠机体投影线与极淡网格，理论上够用；若截图显示不可读，再补一条 200 m 等高的淡横线。
